# 阶段 4：修主张、核引文、再润色

顺序：`ref-verify` 核文献身份和内容 → 对照本研究数据审计主张 → 据证据修订 → `anti-defensive-writing` → 复查数字、引用、限定词和力度。

## 主张审计提示词（对应 PDF）

```text
请审计 {实际稿件版本} 的 Discussion，并检查其他章节中影响主要结论的主张，生成 claim-audit.md。
可用材料：{证据卡、结果表、图注、参考文献列表、原文的真实路径}
逐句输出：
1. C-ID、版本、段落位置与原句；
2. 核心主张；
3. 对应数据或引文位置；
4. 主张与证据是否贴合（支持/部分支持/不支持/相矛盾/未核验）；
5. 可直接替换的英文修订句；
6. 仍需作者提供的材料。
保留研究对象、真实数据方向和引用编号；引文本身有错时单独标记并记录修正，不静默错配。
DOI 存在不等于支持主张，文献机制不能替代本研究测得的机制。
```

## 引文核验提示词

```text
使用 ref-verify 检查 {参考文献文件} 与 {主张列表}。
先核对题名、作者、年份、DOI、文献身份；再核对相应深度的内容并检查撤稿状态。
总体发现可用明确支持它的摘要；机制、方法、参数、表格数字需对应全文。
来源、原文位置、查询日期、状态和缺项保存为 citation-audit.md。
网络错误、限流、全文不可用保留未核验，不据此判为伪造；不根据记忆填 DOI 或原文。
```

按 ref-verify 的 availability 流程检查本地 CLI，Python 必须 3.10+；可用时按说明执行，结果保存到项目 audit 目录。命令输入限必要书目元数据或经授权的内容。摘要匹配/元数据 PASS 不等于完整主张核验。

## 润色提示词

```text
使用 anti-defensive-writing 修订证据审计后的 {稿件/段落}。
删除无信息铺垫、重复免责声明和叠加保留措辞，使论证清楚直接。
保留必要范围、统计不确定性、阴性结果、方法限制和引用。
不把相关性写成因果，不为语气强加入“显著”“证实”等超出证据的词。
以审计后主张为上限，保存 manuscript-audited-vN.md 和修改记录。
最后对照输入检查数字、单位、组别、方向、引文键、因果力度及限制条件。
```

完成条件：关键主张有足够深度的证据，或已收回/收窄至证据支持范围；审计与最终修订句对应。关键矛盾、核心引文缺证、润色导致力度升级时保持 partial。非关键未核验项明确保留，不声称投稿审核通过。
